## Key Findings

### 🔴 Critical: Ollama CVE-2026-7482 — Remote Memory Leak (3 days ago)
A **critical vulnerability** (CVE-2026-7482) in Ollama allows remote attackers to leak process memory via crafted GGUF files. Over **300,000 Ollama servers** are estimated to be exposed publicly. If running Ollama, update immediately.

Separately, CVE-2026-2069 (buffer overflow in llama.cpp) was patched in February — ensure your llama.cpp install is up to date via patch #18993.

### 🟡 Quantization: Unsloth Dynamic v2.0 GGUFs (April 22, 2026)
Unsloth released **Dynamic v2.0 quantization**, a major upgrade over previous quants. Benchmarks show it outperforming leading quantization methods while maintaining model quality — significant for anyone running SLMs on constrained hardware (8–24GB VRAM).

### ⚡ Runtime Performance: llama.cpp Now 1.5–1.8× Faster Than Ollama
Community benchmarks confirm **llama.cpp directly** outperforms Ollama on the same hardware by a significant margin. One migration guide (April 2026) documents the switch, citing both speed gains and immediate access to new GGUF formats. Ollama has also moved to linking ggml directly rather than via llama.cpp as a library.

## Implications for Karen's Stack
- Security audit needed: check Ollama version on this machine (`ollama --version`) and update if exposed
- llama.cpp remains the performance leader for direct inference — relevant for BitNet and local GGUF workflows
- Unsloth Dynamic v2.0 worth testing for improved quality/size ratio on small models
