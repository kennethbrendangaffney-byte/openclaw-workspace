## 1. llama.cpp - The Gold Standard for Local Inference

### Current Status (May 2026)
- **Repository:** Moved to `ggml-org/llama.cpp` (formerly ggerganov)
- **Active development:** Multiple commits daily, very active project
- **Latest releases:** b5000+ series with continuous improvements

### Key Features for Local/CPU Inference
- **Plain C/C++ implementation** - zero dependencies
- **Broad quantization support:** 1.5-bit, 2-bit, 3-bit, 4-bit, 5-bit, 6-bit, and 8-bit integer quantization
- **CPU optimizations:**
  - AVX, AVX2, AVX512 and AMX support for x86
  - ARM NEON, Accelerate and Metal frameworks for Apple Silicon
  - RVV, ZVFH, ZFH for RISC-V
- **CPU+GPU hybrid inference** - partially accelerate models larger than VRAM
- **New WebUI** - guide at discussions/16938
- **Multimodal support** in llama-server (PR #12898)
- **HuggingFace integration:**
  - Models downloaded with `-hf` stored in standard HF cache
  - HF Inference Endpoints support GGUF out of the box
  - GGUF editor available

### Model Support
Extensive - LLaMA, Mistral, Mixtral, Qwen, Gemma, DeepSeek, Falcon, Phi, Granite, BitNet, and many more.

### Installation Options
- brew, nix, winget
- Docker
- Pre-built binaries from releases
- Build from source

## 2. BitNet - 1.58-bit Ternary Quantization

### Overview
- **Official repo:** `microsoft/BitNet`
- **Based on:** llama.cpp framework
- **Quantization:** 1.58-bit ternary (-1, 0, +1 weights)

### Performance Claims (from Microsoft)
- **ARM CPUs:** 1.37x to 5.07x speedup, 55.4% to 70.0% energy reduction
- **x86 CPUs:** 2.37x to 6.17x speedup, 71.9% to 82.2% energy reduction
- **100B model on single CPU** at human reading speed (5-7 t/s)

### Latest Optimizations (Jan 2026)
- Parallel kernel implementations with configurable tiling
- Embedding quantization support
- **Additional 1.15x to 2.1x speedup** over original implementation

### Supported Models

## 3. Small Model Landscape (1B-8B) - 2026

- **Sizes:** 3B, 8B, 30B dense models
- **Training:** ~15T tokens, 5-phase pipeline
- **Context:** Up to 512K tokens (long-context extension)
- **License:** Apache 2.0

## 4. Quantization Techniques

### GGUF Format (llama.cpp)
- **1.5-bit to 8-bit** integer quantization
- **Custom CUDA kernels** for GPU
- **CPU-optimized** inference paths
- **Trade-off:** Quality vs. speed/memory

### BitNet 1.58-bit
- **Ternary weights:** -1, 0, +1
- **No multiplications** during inference (bitwise ops)
- **Lookup table** methodology from T-MAC
- **Lossless inference** for 1-bit models

### ExLlamaV2 / EXL2
- **4-bit GPTQ** with optimal bpw (bits-per-weight)
- **Good for GPU** inference
- **Not ideal for CPU**

### MLX (Apple Silicon)
- **Apple-optimized** framework
- **Transformers to MLX** porting skill available
- **Good for Mac** local inference

## 5. CPU Inference Optimization Strategies

### For Low-RAM Systems (like ours: 24GB)
1. **Use small models:** 2B-4B parameters
2. **Aggressive quantization:** Q4_K_M, Q3_K_S, or BitNet 1.58-bit
3. **llama.cpp with CPU flags:** AVX2/AVX512 if available
4. **Context length:** Reduce to what's needed (default 4K, not 128K)
5. **Batch size 1:** For interactive use

### Recommended Stack for Our System
- **llama.cpp** as inference engine
- **qwen3.5:4b** (3GB) - fast general tasks
- **llama3.1:8b** (5.7GB) - quality reasoning
- **BitNet 2B** (1.1GB) - ultra-efficient fallback
- **nomic-embed-text** (274MB) - embeddings

### Emerging Trends
1. **Code agents** transforming open source contributions (2026)
2. **Skills** for automated model porting (MLX, transformers)
3. **Long-context** becoming standard (512K-1M tokens)
4. **Agent-optimized** models (tool use, reasoning preservation)
5. **Edge deployment** focus (Falcon-E, small Qwen)
