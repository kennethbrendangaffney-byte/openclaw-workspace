## 1. 2026 Cybersecurity Threat Landscape

### Key Threats Identified

| Threat | Severity | Notes |
|--------|----------|-------|
| **Supply Chain Attacks** | Critical | Major supply chain breaches quadrupled over past 5 years (IBM X-Force). Attackers target vendors, open-source dependencies, CI/CD workflows |
| **Credential-Based Attacks** | Critical | 79% of Linux attacks use NO malware — attackers use stolen credentials and "live off the land" with built-in tools (bash, cron, curl) |
| **SSH Brute Force** | High | 89% of Linux endpoint attacks involve credential stuffing/brute force against exposed SSH (port 22) |
| **Privilege Escalation CVEs** | High | 5,530 kernel CVEs in 2025 (highest on record). eBPF subsystem increasingly targeted |
| **Unauthenticated Exploits** | High | 56% of tracked vulnerabilities require NO authentication to exploit |
| **AI-Assisted Phishing** | Rising | 300,000+ ChatGPT credentials found for sale on dark web in 2025. AI agents create new attack surfaces |
| **Cryptojacking** | Moderate | Silent CPU theft on unmonitored servers/IoT devices. Wants to stay invisible |
| **Public-Facing App Exploitation** | High | 44% YoY increase in exploitation of public-facing applications |

### Regional Shift
- North America became most attacked region in 2025 (29% of incidents, up from 24%)
- Attackers don't need zero-days — just valid credentials and patience

## 2. Linux Hardening Best Practices (2026)

### SSH Hardening (Priority #1)
```bash
# Disable password authentication — use key-based only
sudo sed -i 's/^#*PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo systemctl restart sshd

# Check brute force attempts
grep "Failed password" /var/log/auth.log | wc -l

# See top attacking IPs
grep "Failed password" /var/log/auth.log | awk '{print $11}' | sort | uniq -c | sort -rn | head -20
```

**Additional SSH hardening:**
- Change default port (22) to non-standard port
- Disable root login: `PermitRootLogin no`
- Use `AllowUsers` or `AllowGroups` to restrict access
- Enable `MaxAuthTries 3`
- Consider port knocking or single packet authorization (SPA)

### Essential Hardening Checklist

| Layer | Action | Tool/Method |
|-------|--------|-------------|
| **Kernel** | Apply patches promptly | `unattended-upgrades`, `dnf-automatic` |
| **Kernel** | Disable unprivileged eBPF if not needed | sysctl `kernel.unprivileged_bpf_disabled=1` |
| **Network** | Host firewall — allow only required ports | UFW (Ubuntu), nftables, firewalld |
| **Auth** | Key-based SSH only, no passwords | sshd_config |
| **Auth** | Strong sudo policies | Audit `/etc/sudoers`, avoid NOPASSWD |
| **Monitoring** | Intrusion detection | CrowdSec, Fail2Ban |
| **Policy** | Mandatory access controls | AppArmor (Ubuntu) or SELinux (RHEL) |
| **Audit** | System auditing | auditd, Lynis |
| **Containers** | Run containers as non-root | Docker user namespaces, rootless Podman |
| **Secrets** | No hardcoded credentials | HashiCorp Vault / OpenBao |

### Recommended Tools

| Tool | Purpose | Notes |
|------|---------|-------|
| **CrowdSec** | Collaborative intrusion prevention | 60x faster than Fail2Ban, community threat intel, built-in WAF |
| **Fail2Ban** | Log-based IP banning | Classic, battle-tested, perfect complement to CrowdSec |
| **Lynis** | Security auditing | Comprehensive system audit with recommendations |
| **auditd** | Kernel-level auditing | Track system calls, file access, authentication |
| **AppArmor** | Mandatory access control | Default on Ubuntu, profile-based restrictions |
| **UFW** | Simple firewall frontend | Easy iptables management |

## 4. Personal OPSEC (Operational Security)

### Core Principles
1. **Assume breach, reduce exposure** — Don't try to build an unhackable system; build one where attackers can't do much
2. **Audit configurations more than you scan for malware** — 79% of attacks use no malware
3. **Least privilege everywhere** — Every service, every user, every container

### Practical Daily Habits

| Habit | Implementation |
|-------|---------------|
| **Unique passwords** | Password manager (Vaultwarden) with 20+ character random passwords |
| **2FA/MFA everywhere** | Hardware keys (YubiKey) or TOTP (Aegis, andOTP) — avoid SMS |
| **Separate email for critical accounts** | Dedicated email for banking, government, domain registrar |
| **Monitor auth logs** | Weekly check of `/var/log/auth.log` for anomalies |
| **Keep software updated** | Enable automatic security updates |
| **Minimize attack surface** | Disable unused services, close unnecessary ports |
| **Backup encryption** | Encrypt backups before uploading to cloud storage |
| **Separate admin access** | VPN-required access for admin panels, not public internet |

### Threat Modeling for Individuals
1. **Identify assets** — What data/devices matter most?
2. **Identify threats** — Who might target you and why?
3. **Assess vulnerabilities** — Weak passwords? Unpatched systems? Exposed services?
4. **Implement controls** — Match controls to realistic threats (don't over-engineer)
5. **Review regularly** — Threats evolve; revisit quarterly
