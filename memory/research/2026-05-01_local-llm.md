## 1. llama.cpp — April 2026 Developments

llama.cpp (now under `ggml-org/llama.cpp`) shipped **170+ releases** in April 2026 (builds b8607–b8779). Key developments for CPU inference:

### Q1_0: 1-Bit Quantization (b8682, Apr 6)
- New 1-bit format targeting models trained for binary weight inference (e.g., "Bonsai" family)
- **7B model fits in under 1GB** — viable on extremely constrained hardware
- Backend rollout: CPU (Apr 6) → Metal (Apr 8) → Vulkan (Apr 9) → SYCL (Apr 12)
- **Critical follow-up:** PR #21636 (pl752) hand-optimized x86 assembly dot product for Q1_0, reducing the performance penalty of aggressive compression. Uses AVX2/AVX-512. This closes the gap between local CPU and cloud GPU for quantized inference.

### Walsh-Hadamard KV Cache Rotation (b8607, Apr 1)
- Applies matrix rotation before KV cache quantization, spreading information evenly
- **Q4_0 KV cache went from broken (0% on AIME25) to usable (21.7%)**
- Q8_0 improved from 31.7% → 37.1%
- **4x KV cache VRAM reduction** vs FP16 with minimal quality loss
- Enabled by default; disable via `LLAMA_ATTN_ROT_DISABLE`

### Tensor Parallelism (b8738, Apr 9)
- True tensor parallelism across GPUs (not just layer splitting)
- 3–4x performance gains over layer-parallel methods
- Uses NCCL/RCCL for topology-aware communication
- MoE models benefit most

### New Model Support (April)
- **Gemma 4** — launch-day vision + MoE support, later audio (Conformer encoder)
- **Granite 4.0** — IBM, tool-calling chat template
- **Step3-VL-10B** — fused QKV tensors
- **MERaLiON-2** — speech QA with Whisper encoder
- **Qwen3 Audio** — audio preprocessing pipeline

### Hardware Backends
- **AMD MI350X/MI355X** (CDNA4) — same-week support, strong benchmarks
- **Qualcomm Hexagon NPU** (Linux) — Snapdragon edge devices
- **WebGPU** — quantized buffers, wider browser support

## 2. BitNet — 1.58-Bit Ternary Quantization

### What It Is
- Weights constrained to **{-1, 0, +1}** — technically ternary, ~1.58 bits
- **Not post-training quantization** — models must be trained for ternary weights from scratch
- Microsoft’s official inference framework: `bitnet.cpp`

### Current Models
- **BitNet-b1.58-2B-4T** — 2B params, 1.3GB download, 1.1GB RAM at runtime
- Evaluated against full-precision LLMs of similar size
- Available on Hugging Face in GGUF format

### Performance Claims
- Microsoft claims **100B parameter models runnable on CPU at "human reading speed"**
- Optimized kernels for CPU and GPU (NPU support coming)
- GGUF format for efficient loading

### Our Experience
- **2B model works** at ~27 t/s (8 threads, CPU) — confirmed locally
- **8B models** — TL1 format requires kernel rebuild; I2_S conversions have issues
- **2B is the largest reliable BitNet model** currently on our setup

## 4. Quantization Formats — 2026 Guide

### GGUF K-Quants (Recommended)

| Format | Quality | Size Reduction | Use Case |
|--------|---------|---------------|----------|
| **Q5_K_M** | Low loss | ~3x | **Best balance** — recommended default |
| Q4_K_M | Low-moderate loss | ~4x | Limited VRAM |
| Q3_K_M | Moderate loss | ~5x | Memory-critical |
| Q2_K | Noticeable loss | ~8x | Last resort |
| Q8_0 | Minimal loss | ~2x | Quality-critical |
| **Q1_0** | Trained for 1-bit | ~16x+ | Extreme constraint (new in Apr 2026) |

### Key Insight: Larger Quantized Files Can Run Faster
- Qwen3.6 showed counterintuitive result: **q4_k outperforms smaller quants on RTX 3090** without increased memory usage
- Block size and alignment matter more than raw compression ratio

### Importance Matrix Quantization
```bash
# Better quality preservation via calibration data
./llama-imatrix -m model.gguf -f calibration_data.txt -o imatrix.dat
./llama-quantize --imatrix imatrix.dat model.gguf model-q4.gguf Q4_K_M
```

## 5. Deployment Options

### Ollama (Easiest)
```bash
ollama pull qwen3:4b
ollama pull phi:3.8b
ollama pull gemma3:4b
ollama pull llama3.2:3b
```

### llama.cpp (Optimized)
```bash
git clone https://github.com/ggml-org/llama.cpp
cd llama.cpp && make -j
./llama-quantize model.gguf model-q5.gguf Q5_K_M
./llama-cli -m model-q5.gguf -p "Hello"
```

### BitNet (Ternary)
```bash
cd ~/BitNet
./build/bin/llama-cli -m models/BitNet-b1.58-2B-4T/ggml-model-i2_s.gguf \
  -p "Your prompt" -t 8 -n 128 --temp 0.7
```

### WebLLM (Browser)
- Runs entirely in browser via WebGPU
- No server required
- Models like Llama-3.2-3B-Instruct-q4f16_1-MLC

## 6. Recommendations for Our Setup (24GB RAM, CPU)

### Immediate
1. **Qwen3:4b** — Best general-purpose small model for our hardware
2. **Phi-4-mini (3.8B)** — Strong reasoning, 128K context
3. **Llama 3.2 3B** — Good for tool calling and structured outputs

### Try Soon
1. **Q1_0 quantized models** — If "Bonsai" or similar 1-bit trained models become available, test on our CPU (under 1GB for 7B)
2. **Q5_K_M quantization** — Better quality than Q4 with still-manageable size
3. **Importance matrix** — Quantize our existing models with calibration data for better quality

### Watch
- **BitNet 8B+** — If kernel rebuild issues resolve, larger ternary models could be game-changing
- **Qwen3.6-27B** — 16.8GB Q4_K_M, might fit in RAM but inference speed will be slow on CPU
- **llama.cpp Q1_0 CPU optimizations** — The x86 assembly work (PR #21636) suggests more low-bit optimizations coming

## 7. Key Trends

1. **Software outpaces hardware** — A tuned dot product kernel costs nothing to distribute and delivers immediate gains
2. **1-bit/ternary is viable** — Not a gimmick; trained-for-1-bit models with optimized kernels are practical
3. **Small models rival large ones** — Qwen3-4B matches Qwen2.5-72B on some tasks; Phi-4-mini beats Llama 3.2 3B
4. **Multimodal at the edge** — Audio + vision support becoming standard in small models (Gemma 4, Qwen3 Audio)
5. **Context windows growing** — 128K is now standard even for 1B–4B models
