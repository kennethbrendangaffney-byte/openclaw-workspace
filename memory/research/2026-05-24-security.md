## Findings

- **CVE-2026-7482 "Bleeding Llama" (Critical — Ollama):** A heap out-of-bounds read in Ollama's GGUF model loader allows unauthenticated memory disclosure. 175,000+ Ollama instances were publicly exposed at time of disclosure (May 5). Patch to latest version. Also two Windows-specific CVEs — CVE-2026-42248 and CVE-2026-42249 — allow the Windows auto-updater to be weaponised for covert executable placement and RCE.

- **CVE-2026-33579 (High — OpenClaw):** An authentication bypass in OpenClaw's `/pair approve` endpoint allows unauthorised pairing/approval without valid credentials. Disclosed April 6, 2026. If running OpenClaw on an exposed interface, ensure the pairing endpoint is not internet-accessible and verify the patch is applied.

- **Active Supply Chain Surge (npm/PyPI):** The "Mini Shai-Hulud" campaign published hundreds of malicious package versions across npm and PyPI; it spread to Mistral AI integrations. Separately, Vercel disclosed an OAuth-based supply-chain breach (April 19) exposing internal system access and platform environment variables. npm/PyPI supply-chain attacks surged ~38% in Q1 2026 vs prior quarter.

## Recommendations for Ken's Setup
- **Ollama:** Restrict to local interface only (`OLLAMA_HOST=127.0.0.1`); do not expose port publicly.
- **OpenClaw:** Verify gateway is not listening on 0.0.0.0 without firewall; `/pair approve` should be LAN-only at most.
- **Python/npm:** Audit `requirements.txt` and `package.json` against the Mini Shai-Hulud blocklist; pin transitive deps where possible.
