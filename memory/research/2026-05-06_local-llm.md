# Local LLM Research Summary — 2026-05-06

## Overview

This research covers the latest developments in local LLM deployment, quantization techniques, small models (1B-8B parameters), and efficient CPU inference. Focus areas: llama.cpp, BitNet, and small model deployment strategies.

## 1. llama.cpp — Latest Developments (May 2026)

### Current State
- **Repository:** Moved to `ggml-org/llama.cpp` (formerly `ggerganov/llama.cpp`)
- **Latest release:** b9045 (May 6, 2026)
- **Very active development:** Multiple releases per day

### Key Recent Features
- **Granite Speech Support:** Added support for IBM Granite 4.0 1B speech model with Conformer encoder, QFormer projector, and log-mel spectrogram processing
- **Multi-modal capabilities:** Continued expansion of mtmd (multi-text multi-dimensional) support
- **Platform coverage:** Extensive binary releases for:
  - macOS (Apple Silicon + Intel)
  - Linux (x64, arm64, s390x)
  - Windows (x64, arm64)
  - Android (arm64)
  - GPU backends: CUDA 12/13, Vulkan, ROCm 7.2, OpenVINO, SYCL

### Implications for Local Deployment
- llama.cpp remains the gold standard for local inference
- Rapid iteration suggests strong community and corporate backing
- Multi-modal expansion (speech, vision) makes it increasingly versatile
- Wide platform support means deployment flexibility across devices

## 2. BitNet — 1.58-bit Ternary Quantization

### Current State (May 2026)
- **Official repo:** `microsoft/BitNet`
- **Status:** Mature, with GPU support added and ongoing CPU optimizations

### Key Technical Details
- **Quantization:** 1.58-bit ternary weights (-1, 0, +1)
- **Speedups:**
  - ARM CPUs: 1.37x to 5.07x (larger models = greater gains)
  - x86 CPUs: 2.37x to 6.17x
- **Energy reduction:**
  - ARM: 55.4% to 70.0%
  - x86: 71.9% to 82.2%
- **Scalability:** Can run 100B BitNet model on single CPU at human reading speed (5-7 t/s)

### Latest Optimizations (Jan 2026)
- Parallel kernel implementations with configurable tiling
- Embedding quantization support
- Additional 1.15x to 2.1x speedup over original implementation

### Supported Models

|-------|-----------|----------|---------|---------|----------|---------|---------|

## 3. Small Models (1B-8B) — 2026 Landscape

### IBM Granite 4.1 (Released April 2026)
- **Sizes:** 3B, 8B, 30B dense models
- **Training:** ~15T tokens, 5-phase pipeline
- **Context:** Up to 512K tokens (long-context extension)
- **License:** Apache 2.0
- **Key innovation:** 8B instruct matches previous 32B MoE performance
- **Architecture:** GQA, RoPE, SwiGLU, RMSNorm

### DeepSeek-V4 (Released April 2026)
- **Sizes:** V4-Pro (1.6T total, 49B active), V4-Flash (284B total, 13B active)
- **Context:** 1M tokens
- **Architecture:** MoE with hybrid attention (CSA + HCA)
- **Efficiency:** 27% of FLOPs vs V3.2, 10% KV cache memory
- **Target:** Agentic workflows with interleaved thinking across tool calls

### NVIDIA Nemotron 3 Nano Omni (April 2026)
- **Focus:** Long-context multimodal (documents, audio, video)
- **Target:** Agent applications

### Key Trends in Small Models
1. **Quality over quantity:** Rigorous data curation beats raw scale
2. **Long context:** 512K-1M tokens becoming standard
3. **Agent-optimized:** Tool use, reasoning preservation, sandbox training
4. **Dense > MoE (at small scale):** Granite 4.1 shows dense 8B can match 32B MoE

## 4. Quantization Techniques — Current State

### Established Methods
- **Q4_K_M, Q5_K_M, Q6_K:** llama.cpp K-quants (good quality/size tradeoff)
- **IQ-quants:** Improved quantization (IQ4_XS, etc.) — better perplexity retention
- **GPTQ/AWQ:** 4-bit post-training quantization for GPU

### Emerging Techniques
- **BitNet 1.58-bit:** Ternary (-1, 0, +1) — extreme compression
- **FP8/FP4:** DeepSeek V4 uses FP8 for KV cache, FP4 for indexing
- **Embedding quantization:** BitNet now supports quantizing embeddings too

### Recommendations by Use Case
| Scenario | Quantization | Notes |
|----------|-------------|-------|
| Maximum quality | Q6_K or IQ4_XS | Minimal loss |
| Balanced | Q4_K_M | Standard recommendation |
| Size-constrained | Q3_K_M or BitNet I2_S | Significant compression |
| Extreme edge | BitNet TL1/TL2 | Ternary, fastest inference |
| GPU inference | GPTQ 4-bit or AWQ | Optimized for CUDA |

## 5. Efficient CPU Inference — Strategies

### Framework Comparison
| Framework | Best For | Notes |
|-----------|----------|-------|
| llama.cpp | General purpose | Most features, widest model support |
| BitNet (bitnet.cpp) | Ternary models | Fastest for 1.58-bit models |
| T-MAC | General low-bit | Beyond ternary, lookup-table based |
| ONNX Runtime | Cross-platform | Good for deployment |
| MLX (Apple) | Apple Silicon | Native performance on Mac |

### Optimization Techniques
1. **Threading:** Match CPU cores (8 threads optimal for many systems)
2. **Memory bandwidth:** Quantized models are memory-bound, not compute-bound
3. **K-quants:** Use K-quant variants for better cache locality
4. **Flash Attention:** When available, reduces memory overhead
5. **KV cache quantization:** DeepSeek V4 shows FP8 KV cache reduces memory 10x

### Hardware Considerations
- **ARM:** BitNet shows excellent ARM optimization (Apple Silicon, mobile)
- **x86:** llama.cpp + AVX2/FMA instructions; BitNet 2-6x speedups
- **RAM:** 24GB can run 8B models comfortably; 100B BitNet models possible on single CPU
