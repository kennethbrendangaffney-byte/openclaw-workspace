### 2. Gemma 4 — New Google Release (April 2026)

Google launched Gemma 4 on April 2, 2026 with four sizes:
- **E2B** (effective 2B) — ultra-efficient
- **E4B** — balanced
- **26B MoE** — Mixture of Experts, 4B active parameters
- **31B dense** — frontier-level quality

Gemma 4 immediately became the strongest open model for agent tasks in the sub-32B range. The MoE variant is particularly interesting — 26B total params but only ~4B active at inference time, giving frontier quality at mid-range VRAM costs.

## Quantization Techniques

### Traditional GGUF Quantization (llama.cpp)

| Format | Bits | Use Case | Quality Loss |
|--------|------|----------|-------------|
| Q4_K_M | 4-bit | Default recommendation | Minimal |
| Q5_K_M | 5-bit | Better quality, slightly larger | Very low |
| Q8_0 | 8-bit | Near-lossless | Negligible |
| Q3_K_M | 3-bit | Tight memory constraints | Noticeable |

**Rule of thumb:** Q4_K_M is the sweet spot for most deployments. A 7B model at Q4 needs ~3.5-5GB VRAM vs 14-16GB at FP16.

### Turbo Quantization (2026 Breakthrough)

Google Research's Turbo Quantization (presented at ICLR 2026) is a **two-stage KV cache compression** algorithm:

1. **PolarQuant (b-1 bits):** Random orthogonal rotation + polar form conversion removes per-block normalization constants
2. **QJL Residual Correction (1 bit):** Johnson-Lindenstrauss transform stores only sign bits as bias correction

**Results:**
- KV cache compressed to **3-4 bits per element**
- **4-6x reduction** in KV cache memory usage
- At 4K tokens: saves >1GB
- At 8K+ tokens: saves 2GB+ per model
- 2-3x higher token throughput under memory pressure
- **Training-free and model-agnostic**

Already integrated into llama.cpp with Metal kernels for Apple Silicon. 4-bit compression is indistinguishable from FP16; 3-bit shows degradation on models under 8B.

### BitNet — 1.58-bit Ternary Quantization

Microsoft's BitNet b1.58 uses ternary weights (-1, 0, +1) — approximately 1.58 bits per weight.

**Current status (May 2026):**
- **bitnet.cpp** is the official inference framework (based on llama.cpp)
- **BitNet-b1.58-2B-4T** is the largest reliable working model (2.4B params, 1.3GB download, 1.1GB RAM)
- Speed: ~27 tok/s on CPU (8 threads)
- **100B model can run on a single CPU** at human reading speed (5-7 tok/s)

**Kernel support:**
- I2_S format: ✅ x86 and ARM
- TL1 format: ❌ x86, ✅ ARM (requires kernel rebuild)
- TL2 format: ✅ x86, ❌ ARM

**Limitation:** 2B is currently the largest reliable BitNet model. 8B models have conversion issues.

**Performance gains:**
- ARM CPUs: 1.37x-5.07x speedup, 55-70% energy reduction
- x86 CPUs: 2.37x-6.17x speedup, 72-82% energy reduction

## llama.cpp Updates (2026)

### Key Improvements

1. **TurboQuant integration** — KV cache compression with Metal kernels for Apple Silicon
2. **Metal GPU backend** — Continued optimization for Apple Silicon M-series
3. **Speculative decoding** — Faster inference via draft model acceptance
4. **MoE model support** — Efficient Mixture of Experts inference
5. **Q4_K_M remains the default** quantization recommendation

### Performance Context

- **CPU-only with Q4:** 2-6 tok/s for 3-7B models (viable for batch/non-interactive)
- **Apple Silicon (MLX vs llama.cpp):** MLX 20-87% faster for models under 14B; gap collapses at larger models
- **Memory bandwidth > raw compute** for token throughput

## Relevance to Our Setup

**Current hardware:** 24GB RAM, CPU-only (no GPU)

**Current models:**
- qwen3.5:4b (3GB) — fast general tasks
- llama3.1:8b (5.7GB) — quality reasoning
- nomic-embed-text (274MB) — embeddings
- BitNet 2B (1.1GB RAM) — efficient inference

**Observations:**
1. Our qwen3.5:4b is well-positioned — Qwen 3 4B is a top-ranked small model
2. llama3.1:8b could be upgraded to **Llama 3.3 8B** for better instruction following
3. **Phi-4-mini 3.8B** would be an excellent addition for reasoning tasks (~3GB)
4. **Gemma 3 4B** would add multimodal/vision capability
5. BitNet 2B is working but limited — the 1.58-bit quantization is promising but model availability is constrained
6. Turbo Quantization in llama.cpp could help extend context length on our 24GB system

**Potential upgrades:**
- Replace llama3.1:8b with llama3.3:8b (better quality, same size)
- Add phi:3.8b for reasoning tasks
- Consider Gemma 3 4B for vision tasks
- Monitor BitNet for larger model releases (8B+ would be a game-changer)
