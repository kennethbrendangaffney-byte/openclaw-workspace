## 1. llama.cpp — Latest Developments (May 2026)

**Repository:** https://github.com/ggml-org/llama.cpp

### Recent Highlights (b5190-b5200+)
- **Internal AllReduce kernel for CUDA** — NCCL-free tensor parallelism for multi-GPU setups. Single-phase CUDA kernel pipelines D2H copy, cross-GPU handshake, and reduction. Currently scoped to 2 GPUs, FP32, tensors ≤256KB.
- **AllReduce hang watchdog** — Debug kernel variant with per-GPU spin diagnostics. Host-side blocking poll detects hangs and logs diagnostics. Zero overhead on production path.
- **Blackwell PCIe fix** — Added `__threadfence_system()` before arrival signal write to prevent intermittent deadlocks on RTX 5090 (Blackwell, PCIe-only).
- **llama-bench improvements** — `--override-tensors` / `--override-tensor` arg added for tensor override testing. `--reduction-provider` / `-rp` flag for AllReduce provider selection.
- **CMake NCCL detection** — Improved FindNCCL.cmake for source-tree builds, static/dynamic switch via `GGML_CUDA_NCCL_STATIC`.

### Key Takeaway
llama.cpp continues rapid iteration on both CPU and GPU paths. The AllReduce work shows serious engineering for multi-GPU inference, but for our use case (single machine, CPU-focused), the core GGML CPU backend remains the workhorse.

## 2. BitNet — 1-bit LLM Inference (Microsoft)

**Repository:** https://github.com/microsoft/BitNet

### Status (May 2026)
- **bitnet.cpp** is the official inference framework for 1-bit (ternary, 1.58-bit) LLMs
- Based on llama.cpp framework with optimized lookup-table kernels (built on T-MAC methodology)
- **CPU speedups:** 1.37x-5.07x on ARM, 2.37x-6.17x on x86
- **Energy reduction:** 55-70% on ARM, 72-82% on x86
- **Claim:** Can run 100B BitNet model on a single CPU at human reading speed (5-7 t/s)

### Latest Optimization (January 2026)
- Parallel kernel implementations with configurable tiling
- Embedding quantization support
- **1.15x-2.1x additional speedup** over original implementation across platforms

### Supported Models & Kernels

| Model | Params | x86 I2_S | x86 TL1 | x86 TL2 | ARM I2_S | ARM TL1 | ARM TL2 |
|-------|--------|----------|---------|---------|----------|---------|---------|
| BitNet-b1.58-2B-4T | 2.4B | ✅ | ❌ | ✅ | ✅ | ✅ | ❌ |
| bitnet_b1_58-large | 0.7B | ✅ | ❌ | ✅ | ✅ | ✅ | ❌ |
| bitnet_b1_58-3B | 3.3B | ❌ | ❌ | ✅ | ❌ | ✅ | ❌ |
| Llama3-8B-1.58-100B-tokens | 8.0B | ✅ | ❌ | ✅ | ✅ | ✅ | ❌ |

| Falcon-E Family | 1B-3B | ✅ | ❌ | ✅ | ✅ | ✅ | ❌ |

### Key Takeaway
BitNet is maturing. The 2B model works well on x86 with I2_S (our current setup). The 8B Llama3-1.58 model is now supported on x86 I2_S — worth testing for quality vs. our current llama3.1:8b. GPU inference kernels also available (added May 2025). NPU support coming next.

## 3. Small Models Landscape (1B-8B) — May 2026

### IBM Granite 4.1 (Released April 2026)
- **Sizes:** 3B, 8B, 30B dense models
- **License:** Apache 2.0
- **Training:** ~15T tokens, 5-phase pipeline including long-context extension to 512K tokens
- **Architecture:** Dense decoder-only, GQA, RoPE, SwiGLU, RMSNorm
- **Notable:** 8B instruct matches/surpasses previous Granite 4.0-H-Small (32B-A9B MoE)
- **Data quality focus:** Progressive refinement from broad web to curated domain-specific content
- **Post-training:** ~4.1M SFT samples + GRPO with DAPO loss

| Size | Embedding | Layers | Attention Heads | KV Heads | MLP Hidden |
|------|-----------|--------|-----------------|----------|------------|
| 3B | 2560 | 40 | 40 | 8 | 8192 |
| 8B | 4096 | 40 | 32 | 8 | 12800 |
| 30B | 4096 | 64 | 32 | 8 | 32768 |

### DeepSeek-V4 (Released April 2026)
- **Not directly relevant** for local CPU inference (1.6T/284B MoE models)
- **But architecturally interesting:** Hybrid attention (CSA + HCA) for efficient long-context
- **KV cache:** ~2% of standard GQA bfloat16 cache size
- **Context:** 1M tokens
- **Lesson for small models:** Compression + sparse attention techniques may trickle down

### Ollama + MLX (March 2026)
- Ollama now powered by MLX on Apple Silicon (preview)
- Fastest Ollama runtime on Apple silicon
- Not relevant for our Linux/x86 setup but shows ecosystem maturation

## 4. Quantization Techniques — Current State

### Established Methods
| Method | Bits | Status | Notes |
|--------|------|--------|-------|
| Q4_0 / Q4_K_M | 4-bit | Mature | Default for most GGUF models. Good quality/size tradeoff |
| Q5_K_M | 5-bit | Mature | Better quality, ~25% larger than Q4 |
| Q8_0 | 8-bit | Mature | Near-lossless, 2x size of Q4 |
| IQ quants (Q4_K_XS, etc.) | 4-bit | Mature | Improved quants with better accuracy |

### Emerging: 1-bit / Ternary
| Method | Bits | Status | Notes |
|--------|------|--------|-------|
| BitNet b1.58 (I2_S) | 1.58-bit | Working | Ternary weights (-1, 0, +1). 1.1GB RAM for 2B model |
| BitNet b1.58 (TL1) | 1.58-bit | Partial | x86 TL1 has issues with larger models |
| BitNet b1.58 (TL2) | 1.58-bit | Partial | Limited model support |

### Key Insight
1.58-bit models are not just smaller — they're **faster** on CPU due to lookup-table kernels avoiding full matrix multiplications. The quality gap is narrowing. For our 24GB RAM machine, a 1.58-bit 8B model would use ~1.5GB RAM — leaving massive headroom.

## 5. Efficient CPU Inference — Practical Notes

### Current System (Our Setup)
- **RAM:** 24GB
- **CPU:** x86_64, 8 threads optimal for BitNet
- **Working models:**
  - qwen3.5:4b (3GB, fast general tasks)
  - llama3.1:8b (5.7GB, quality reasoning)
  - BitNet 2B (1.1GB, 27 t/s, efficient)

### Recommendations for Our Hardware
1. **BitNet 8B (Llama3-8B-1.58)** — Test this. 1.58-bit quantization means ~1.5GB RAM usage. If quality is acceptable, it replaces llama3.1:8b with 4x less RAM and potentially faster inference.
2. **Granite 4.1-3B or 8B** — Apache 2.0, high data quality, strong coding/math. Worth testing against qwen3.5:4b for general tasks.
3. **Stick with llama.cpp backend** — Whether via Ollama or direct, it's the most mature CPU inference engine.

| x86 | 3B | ~4x | ~75% |
| x86 | 8B | ~6x | ~82% |
| x86 | 100B | ~human reading speed | ~82% |
