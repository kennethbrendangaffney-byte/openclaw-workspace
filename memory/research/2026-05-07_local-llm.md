# Local LLM Research Summary - 2026-05-07

## Overview

2026 marks the year of "efficiency" in AI. Small Language Models (SLMs) and edge AI are fundamentally reshaping how AI systems are deployed. The sub-7B category has exploded with competition—Meta, Alibaba, Microsoft, Google, and Hugging Face all releasing models that punch dramatically above their weight class.

**Key insight:** A 4B model in 2026 routinely outperforms a 13B model from 2023. Raw parameter count is now a poor proxy for capability.

## Quantization Techniques (2026)

### GGUF (llama.cpp format) - The Default for Local
**Strengths:**
- Runs on CPU, GPU, or both (CPU offloading)
- Single file format, easy to manage
- Supports mixed quantization (different layers at different precision)
- Best ecosystem support (Ollama, LM Studio, llama.cpp)
- Works on NVIDIA, AMD, Apple Silicon, and CPU-only

**Limitations:**
- Slower GPU inference than GPTQ/AWQ on NVIDIA hardware
- Not used for training, only inference
- Less optimal for high-throughput server use cases

**Recommended GGUF variants:**
| Variant | Description | Best For |
|---------|-------------|----------|
| Q4_K_M | 4-bit K-quant, medium size | Best all-round choice |
| Q4_K_S | 4-bit K-quant, smaller | Tight VRAM budgets |
| Q5_K_M | 5-bit K-quant | When you have headroom over Q4 |
| Q8_0 | 8-bit quantization | Near-FP16 quality |

**Key rule:** A larger model at lower precision almost always beats a smaller model at higher precision. A 70B Q4 outperforms a 7B FP16 despite similar file sizes.

### GPTQ (GPU-optimized)
- Best for NVIDIA GPU inference
- Faster than GGUF on GPU
- Requires GPU for optimal performance
- Less flexible for CPU-only deployment

### AWQ (Activation-aware Weight Quantization)
- GPU-optimized, competitive with GPTQ
- Good for high-throughput scenarios
- NVIDIA-focused

### BitNet / 1.58-bit Quantization (Microsoft) - The Extreme
- **BitNet b1.58-2B-4T** - First open-source native 1-bit LLM at 2B scale
- Weights encoded as ternary values: {-1, 0, +1}
- ~1.58 bits per weight
- 1.3GB download, 1.1GB RAM at runtime
- ~27 tokens/sec on CPU (8 threads)
- Trained on 4-trillion-token dataset
- Enables 100B parameter inference on single CPU
- Official framework: `bitnet.cpp` (Microsoft)
- **Limitation:** Currently 2B is the largest reliable working model

## llama.cpp - The Backbone of Edge Inference (2026)

### Current Status
- Remains the backbone of edge inference in 2026
- Active development with daily releases
- Automatic hardware detection (CPU features, available GPUs)
- Optimal execution paths using SIMD instructions and GPU kernels

### CPU Optimization Features
- **AVX/AVX2/AVX512** support for x86_64
- **NEON/SVE** acceleration for ARM (including Apple Silicon)
- Multi-threading with optimal thread allocation
- CPU offloading for mixed CPU/GPU execution

### Recent Developments (May 2026)
- Granite speech model support (IBM)
- Continued GGUF format evolution
- Improved multimodal support
- Better quantization conversion tools

### Ecosystem Integration
- **Ollama** - Most popular wrapper, easy model management
- **LM Studio** - GUI for model exploration
- **KoboldCPP** - Storytelling/roleplay focused
- **text-generation-webui** - Flexible web interface

## Hardware Requirements for Local Inference

### RAM/VRAM Requirements (Q4 Quantization)
| Model Size | VRAM/RAM Needed | Notes |
|------------|-----------------|-------|
| 1B | ~1-2GB | Runs on any modern device |
| 3-4B | ~2-4GB | Fits on 8GB GPU with headroom |
| 7-8B | ~4-6GB | Requires dedicated GPU or 16GB+ RAM |
| 14B | ~8-10GB | Needs modern GPU or 32GB RAM |

### CPU Inference Performance
- **BitNet 2B:** ~27 t/s (8 threads, x86_64)
- **Qwen3.5-4B Q4:** ~15-25 t/s (modern CPU)
- **Phi-4-mini Q4:** ~10-20 t/s (modern CPU)
- **Gemma 3 4B Q4:** ~12-18 t/s (modern CPU)
