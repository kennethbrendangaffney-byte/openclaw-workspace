## 3. Local / Self-Hosted AI

Self-hosting is now genuinely viable for professional development. The gap between proprietary and open-source has narrowed dramatically.

### Why Self-Host?

- **Privacy:** Data never leaves your infrastructure
- **Cost predictability:** Upfront hardware vs. unpredictable API bills
- **No rate limits:** Capacity matches your hardware
- **No vendor lock-in:** Switch between open-weight models freely
- **Customization:** Fine-tune on your own data

### Best Local Inference Runtimes

| Runtime | Best For | Effort | Speed |
|---------|----------|--------|-------|
| **Ollama** | Easiest start — `ollama pull model` | Minimal | Good |
| **llama.cpp** | Maximum control, custom compilation | High | Best (tuned) |
| **LM Studio** | Visual model management, GUI | Minimal | Good |
| **vLLM** | Production serving, PagedAttention | Medium | Production-grade |
| **Tabby** | Self-hosted Copilot alternative | Medium | Good |

### Best Self-Hosted Coding Models (2026)

| Model | Params | SWE-bench | License | Runs On |
|-------|--------|-----------|---------|---------|
| **GLM-5** | 744B MoE (40B active) | 77.8% | MIT | vLLM/SGLang (80GB+ VRAM) |
| **Kimi K2.5** | 1T MoE | 76.8% | Open | Enterprise hardware |
| **Devstral 2** | 123B | 72.2% | Apache 2.0 | Ollama, llama.cpp |
| **Devstral Small 2** | 24B | 68% | Apache 2.0 | Consumer GPU |
| **Qwen 2.5 Coder** | 7B-72B | — | Apache 2.0 | Ollama (7B on laptop, 32B on desktop) |
| **DeepSeek Coder V2** | Various | — | MIT | Ollama, llama.cpp |
| **MiniMax M2** | 230B MoE (10B active) | — | Open | 8% of Claude's price, 2x speed |

**Hardware guidance:**
- **Laptop (16GB RAM):** Qwen 2.5 Coder 7B or DeepSeek Coder V2 7B via Ollama
- **Desktop with GPU (12GB VRAM):** Qwen 2.5 Coder 32B via Ollama
- **Server (80GB+ VRAM):** GLM-5 or Kimi K2.5 via vLLM — compete with Claude on benchmarks

## 4. AI Image Generation (Local & Cloud)

Running image models locally is now highly viable on consumer GPUs. A 16GB VRAM card can rival Midjourney and DALL-E.

### Hardware Requirements

| Setup | VRAM | Examples |
|-------|------|----------|
| Minimum | 8GB | RTX 3060, RTX 4060 — runs SDXL, FLUX with quantization |
| Sweet spot | 16GB | RTX 4080, RTX 5060 Ti 16GB — runs nearly everything |
| Ideal | 24GB | RTX 3090, RTX 4090 — runs everything without quantization |

### Best Local Image Models (2026)

| Model | Params | VRAM (native) | VRAM (quantized) | Speed | License | Best For |
|-------|--------|---------------|------------------|-------|---------|----------|
| **FLUX.1 Dev** | 12B + 4.5B encoder | ~24GB | Q8: ~12GB, Q4: ~8GB | 15-25s/image | Non-commercial | Best overall quality, photorealism, text rendering |
| **FLUX.1 Schnell** | Same as Dev | ~24GB | Q8: ~12GB | 8-12s/image (4 steps) | **Apache 2.0** | Commercial use, speed |
| **FLUX.2 Klein 4B** | 4B | ~13GB | Fits 16GB natively | 3-5s/image | Check BFL | Best quality-to-VRAM ratio, real-time |
| **FLUX.1 Kontext** | 12B | ~24GB | FP8: ~12GB, FP4: ~7GB | Varies | Non-commercial | Image editing, style transfer, object editing |
| **Stable Diffusion XL** | 2.6B + 6.6B | ~8GB min, 12GB comfy | ~8GB | 8s/image (20 steps) | Open RAIL-M | Largest ecosystem, LoRAs, ControlNet |
| **SD 3.5 Large** | 8B | ~24GB | FP8: ~11GB | Varies | Free <$1M revenue | Improved text rendering over SDXL |
| **Z-Image Turbo** | 6B | 12-16GB | GGUF: ~6GB | 4-6s/image | Open source | Speed demon, bilingual text |
| **PixArt-Sigma** | 0.6B | <8GB | <8GB | Fast | Open source | Low-VRAM systems, up to 4K output |

**Key insight:** FLUX.1 Dev is the quality leader but non-commercial. For commercial work, FLUX.1 Schnell (Apache 2.0) or Z-Image Turbo are the go-tos. SDXL remains unbeatable for niche art styles via community LoRAs.

## 9. Key Trends & Observations

### 1. The Open-Source Gap Is Closing
Proprietary models (GPT-5, Claude 4.6) still lead on absolute benchmarks, but open-source models like GLM-5 (55.00 agentic coding), Kimi K2.5 (77.86 coding), and DeepSeek V3.2 are now genuinely competitive. For many real-world tasks, the difference is negligible.

### 2. Local AI Is Production-Ready
A consumer GPU with 16GB VRAM can now run models that rival cloud services for image generation, coding assistance, and general reasoning. The cost savings are substantial — some teams report 90% reduction in LLM costs by self-hosting.

### 3. Token Efficiency > Subscription Price
Claude Code uses 5.5x fewer tokens than Cursor. At $3-15 per million tokens, the real cost difference is far larger than the $1-4/month subscription gap suggests.

### 4. Free Tiers Are Actually Usable
Gemini CLI (1,000 requests/day), Qwen Code (free API), and GitHub Copilot CLI (50 requests/mo) offer genuinely usable free tiers. For budget-constrained developers, these are viable daily drivers.

### 5. Agentic Coding Is the New Battleground
The shift from "AI assists one developer" to "AI coordinates entire engineering workflows" is happening. Tools like Claude Code, Antigravity, and Kimi K2.5's 100-agent swarm represent a fundamental shift in how code gets written.

### 6. Chinese Models Are Competitive
GLM-5 (Zhipu AI), Kimi K2.5 (Moonshot), Qwen 3.5 Coder (Alibaba), and MiniMax M2 are all top-tier open-weight models. The Chinese AI ecosystem is no longer a follower — it's a leader in several categories.

### 7. Self-Hosting Requires Real Hardware
For serious local coding: 16GB VRAM minimum for good models, 80GB+ for frontier models. For image generation: 16GB is the sweet spot, 8GB is viable with quantization.

### 8. Hybrid Approaches Make Sense
Most teams should start with APIs to validate use cases, then migrate high-volume, sensitive, or stable workloads to self-hosting. Keep APIs for experimentation and low-volume tasks.
