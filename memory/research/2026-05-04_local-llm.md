# Local LLM Research — 2026-05-04

## Executive Summary

The local LLM landscape in 2026 is dominated by three converging trends:
1. **Extreme quantization** (1-bit/1.58-bit ternary weights) making 100B+ models runnable on consumer CPUs
2. **Small dense models** (1B–8B) closing the quality gap with larger counterparts through better data curation
3. **Inference frameworks** (llama.cpp, BitNet, MLX) maturing into first-class deployment platforms with WebUI, multimodal support, and hybrid CPU/GPU execution

For Ken's setup (24GB RAM, no GPU), the most relevant developments are BitNet's continued CPU optimization, llama.cpp's expanding quantization support, and the emergence of high-quality small models (Granite 4.1 3B/8B, Gemma 3 1B) that can run efficiently on his hardware.

## 1. BitNet & 1-bit Inference

### Current State (May 2026)

**Microsoft BitNet** remains the flagship 1-bit inference framework. Key developments:

- **Official 2B model**: `BitNet-b1.58-2B-4T` available on HuggingFace (1.3GB download, 1.1GB RAM at runtime)
- **CPU speedups**: 1.37x–5.07x on ARM, 2.37x–6.17x on x86 compared to full-precision equivalents
- **Energy reduction**: 55–82% less power consumption
- **100B model on single CPU**: Achieves human reading speed (5–7 t/s)

### January 2026 Optimization Update

Major performance improvements via parallel kernel implementations:

- **Parallel weight & activation computation** in W2A8 vet_dot kernel
- **Native I2_S GEMM/GEMV** support integrated into ggml/llama.cpp architecture
- **Configurable tiling**: `ROW_BLOCK_SIZE`, `COL_BLOCK_SIZE`, `PARALLEL_SIZE` tunable per CPU
- **Embedding quantization**: Q6_K format for embeddings reduces memory further with minimal quality loss

### Kernel Formats

| Format | Description | Status |
|--------|-------------|--------|
| I2_S | 2-bit signed ternary (-1, 0, +1) | ✅ Primary, fully integrated |
| TL1 | Ternary lookup table | ❌ x86, ✅ ARM |
| TL2 | Ternary lookup v2 | ✅ x86, ❌ ARM |

### Relevance to Ken's Setup

- **Already running**: BitNet 2B at ~27 t/s on this machine
- **Tunable**: Can optimize `gemm-config.h` for his specific CPU cache
- **Limitation**: 8B models still problematic (TL1 format needs kernel rebuild; I2_S conversions have issues)
- **Action**: Try embedding quantization (`--quant-embd`) for additional speedup

## 2. llama.cpp Developments

### Recent Features (2026)

- **HuggingFace integration**: Models downloaded with `-hf` stored in standard HF cache, shareable with other tools
- **WebUI**: New browser-based interface for llama-server ([discussion #16938](https://github.com/ggml-org/llama.cpp/discussions/16938))
- **Multimodal support**: Vision-language models in llama-server ([PR #12898](https://github.com/ggml-org/llama.cpp/pull/12898))
- **GPT-OSS support**: Native MXFP4 format with NVIDIA collaboration
- **GGUF editor**: Community tool for editing GGUF files
- **VS Code/Vim plugins**: FIM (fill-in-middle) completion extensions

### Quantization Support

llama.cpp now supports:
- 1.5-bit, 2-bit, 3-bit, 4-bit, 5-bit, 6-bit, 8-bit integer quantization
- Custom CUDA kernels (NVIDIA), HIP (AMD), MUSA (Moore Threads)
- Vulkan and SYCL backends
- CPU+GPU hybrid inference for models exceeding VRAM

### Architecture Support

- **Apple Silicon**: ARM NEON, Accelerate, Metal (first-class citizen)
- **x86**: AVX, AVX2, AVX512, AMX
- **RISC-V**: RVV, ZVFH, ZFH, ZICBOP, ZIHINTPAUSE

### Relevance to Ken's Setup

- **Primary inference engine**: Already using via Ollama (which wraps llama.cpp)
- **Direct use case**: Can run `llama-cli` or `llama-server` directly for more control
- **Quantization**: Can create custom GGUF quants from HF models
- **Hybrid inference**: Not relevant (no GPU), but good to know for future hardware

## 3. Small Models (1B–8B) — The Quality Revolution

### IBM Granite 4.1 (April 2026)

Dense decoder-only models with surprisingly strong performance:

| Model | Params | Context | License |
|-------|--------|---------|---------|
| Granite 4.1 3B | 3B | 512K | Apache 2.0 |
| Granite 4.1 8B | 8B | 512K | Apache 2.0 |
| Granite 4.1 30B | 30B | 512K | Apache 2.0 |

**Key innovation**: 8B instruct matches previous 32B MoE model quality through:
- 5-phase pre-training on ~15T tokens
- Progressive data quality annealing
- Long-context extension to 512K tokens
- GRPO with DAPO loss for RL fine-tuning

**Architecture**: GQA, RoPE, SwiGLU, RMSNorm — modern standard

### NVIDIA Nemotron 3 Nano Omni (April 2026)

Multimodal small model (30B-A3B MoE) for document/audio/video:
- Best-in-class document understanding (OCRBenchV2, MMLongBench-Doc)
- 9x higher throughput than alternatives
- Available in BF16, FP8, NVFP4

### DeepSeek-V4 (April 2026)

Not a small model, but architecturally relevant for efficient inference:
- **1M token context window** with efficient KV cache
- Hybrid attention: Compressed Sparse Attention (CSA) + Heavily Compressed Attention (HCA)
- 27% of FLOPs vs V3.2 at 1M tokens, 10% KV cache memory
- Designed specifically for agentic workloads

### Gemma 3 (Google)

Already available in GGUF via llama.cpp:
- `ggml-org/gemma-3-1b-it-GGUF` — ultra-small, decent quality
- Good for testing/development on limited hardware

## 4. Quantization Techniques

### Current Landscape

| Technique | Bits | Status | Use Case |
|-----------|------|--------|----------|
| BitNet b1.58 | 1.58 (ternary) | Production | CPU inference, extreme compression |
| Q4_K_M | 4 | Production | Balanced quality/size |
| Q5_K_M | 5 | Production | Higher quality, larger |
| Q6_K | 6 | Production | Near-lossless, embeddings |
| Q8_0 | 8 | Production | Minimal quality loss |
| MXFP4 | 4 | Emerging | NVIDIA-specific, GPT-OSS |
| NVFP4 | 4 | Emerging | NVIDIA Blackwell |
| FP8 | 8 | Emerging | Training + inference |

### BitNet Specifics

- **1.58-bit ternary**: Weights constrained to {-1, 0, +1}
- **Absmean quantization**: Activations quantized to 8-bit
- **Lookup Table (LUT)**: Inference via precomputed tables, not matrix multiply
- **I2_S format**: 2-bit signed storage, native GEMM/GEMV in ggml

### Embedding Quantization

New technique for further memory reduction:
- Q6_K for embeddings: minimal perplexity impact
- Can be combined with I2_S weight quantization
- Reduces memory footprint for large vocabularies

## 6. Deployment Patterns & Tools

### Ollama

- Still the easiest entry point for local models
- Wraps llama.cpp with simple CLI
- Model library with one-command pulls
- **Caveat**: Large model downloads unreliable (use `wget --continue` + `ollama create`)

### llama.cpp Direct

- More control, better for production
- New WebUI for server mode
- Native multimodal support
- Better quantization options

### BitNet.cpp

- Specialized for 1-bit models
- Fastest CPU inference for supported models
- Requires specific model formats (I2_S, TL1, TL2)

### Transformers.js

- Browser-based inference via WebGPU/WebNN
- Good for client-side deployment
- Chrome extension support
