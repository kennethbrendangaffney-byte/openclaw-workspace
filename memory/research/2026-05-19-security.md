# Security Pulse — 2026-05-19

## CVEs: Ollama in the Fire

- **"Bleeding Llama" — CVE-2026-7482 (Critical):** Unauthenticated memory-leak in Ollama exposes process memory, leaking API keys, prompts, and credentials via just 3 API calls. Affects **300K+ publicly exposed Ollama servers**. Patch immediately or restrict to localhost.
- **CVE-2026-42248 (Windows RCE):** Remote code execution flaw in Ollama for Windows — silent auto-updates may unknowingly install a malicious payload. If you run Ollama on Windows, treat as critical.
- **CVE-2026-7020:** Flaw in Ollama's Tensor Model Transfer Handler lets a remote attacker trigger the vulnerability. Also notable: OpenClaw carries a known SSRF flaw in its Ollama network request handler (CVE tracked at mitfth.com/intel/583416).

## Auth & Token Incidents

- **Vercel breach (April 19, 2026):** OAuth supply-chain compromise gave attackers access to internal systems. Environment variables and secrets in Vercel apps are the primary exposure vector — treat any Vercel-deployed secrets as potentially leaked.
- **APT28 OAuth token theft:** The Russian state-nexus group hijacked **18,000 routers** to harvest OAuth tokens and bypass MFA in sophisticated targeted attacks. Token-based auth without device verification remains a weak link.

## Supply Chain Attacks

- **npm + PyPI + Docker Hub triple-hit (April 21–23, 2026):** Three simultaneous supply-chain campaigns hit all three registries in a 48-hour window — all targeting secrets (API keys, cloud credentials). The pattern is deliberate diversification by threat actors.
- **TanStack / Mini Shai-Hulud worm:** 160+ npm/PyPI packages compromised by a self-replicating worm variant. Hits Mistral AI packages. Check your lockfiles if you pull from either registry.
- **npm/PyPI attacks up 38% in Q1 2026** year-over-year. Open-source package registries are an accelerating threat surface.

## Mitigations

- Restrict Ollama to `localhost` or put behind authenticated reverse-proxy
- Audit Vercel environment variables; rotate any exposed secrets
- Pin exact package versions in `package-lock.json`/`requirements.lock.txt`; enableSigstore/ reproducible builds where possible
- Scan `node_modules`/`site-packages` with `npm audit` / `pip audit` — especially after any `package-lock.json` updates
