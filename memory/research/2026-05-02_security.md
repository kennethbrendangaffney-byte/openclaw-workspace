## 2. Linux Hardening Techniques (2026)

### Immediate Actions (Critical)

1. **SSH Hardening**
   - Disable root login: `PermitRootLogin no`
   - Disable password auth: `PasswordAuthentication no`
   - Use Ed25519 or RSA 4096-bit keys only
   - Change default port (reduces automated scan noise ~95%)
   - Set idle timeouts, disable X11/TCP forwarding
   - Limit to specific users/groups via `AllowUsers`/`AllowGroups`

2. **Patch Management**
   - Enable automatic security updates (`unattended-upgrades` on Ubuntu)
   - Maximum patch latency: critical within 72 hours, high within 14 days
   - Subscribe to distribution security advisory mailing lists
   - Verify all repos use HTTPS

3. **Firewall Configuration**
   - Default deny incoming, allow outgoing
   - UFW as frontend for NFTables (modern replacement for iptables)
   - Only open necessary ports
   - Example:
     ```bash
     sudo ufw default deny incoming
     sudo ufw default allow outgoing
     sudo ufw allow <custom_ssh_port>/tcp
     sudo ufw allow 80/tcp
     sudo ufw allow 443/tcp
     sudo ufw enable
     ```

4. **Intrusion Prevention**
   - **Fail2Ban**: Ban IPs after 3 failed login attempts for 24+ hours
   - Monitor logs for repeated failures
   - Configure aggressive banning policies for 2026 botnet landscape

### Advanced Hardening

5. **Kernel Hardening (sysctl)**
   ```bash
   # IP Spoofing protection
   net.ipv4.conf.all.rp_filter = 1
   net.ipv4.conf.default.rp_filter = 1

   # Ignore ICMP broadcast (Smurf attack prevention)
   net.ipv4.icmp_echo_ignore_broadcasts = 1

   # SYN flood protection
   net.ipv4.tcp_syncookies = 1

   # Disable source routing
   net.ipv4.conf.all.accept_source_route = 0

   # Disable ICMP redirects
   net.ipv4.conf.all.accept_redirects = 0
   net.ipv4.conf.all.send_redirects = 0
   ```

6. **Mandatory Access Control (MAC)**
   - **AppArmor** (Ubuntu default): Simpler, profile-based
   - **SELinux** (RHEL/Fedora): Enterprise-grade, more granular
   - Both can contain damage even when services are exploited
   - Real-world example: Finance environment where attackers compromised web service but couldn't pivot due to SELinux policies

7. **Minimal Installation Principle**
   - Install less, run fewer services
   - Every extra package = more patching, more attack surface
   - Disable unused services
   - Run services as non-root with restricted permissions

8. **File Permissions & Access Control**
   - Eliminate world-writable directories
   - Secure config files (640/600 permissions)
   - Restrict home folder permissions
   - Use `sudo` with limited privileges, not root

### CIS Benchmarks
- **Level 1**: Basic hardening — suitable for most environments
- **Level 2**: High-security environments — more restrictive
- Ubuntu Security Guide (USG) automates CIS/DISA-STIG compliance
- April 2026 CIS update covers cloud, OT, endpoint hardening, supply chain, IAM

## 4. Container Security (2026)

### Podman vs Docker

| Feature | Docker | Podman |
|---------|--------|--------|
| Rootless | Requires explicit config | Default, seamless |
| Daemon | Required (privileged process) | Daemonless |
| Security | Good | Better (no elevated privileges needed) |
| Kubernetes | containerd runtime | Compatible |

**2026 Trend:** DevOps teams migrating to Podman for security. Docker's daemon is a single point of failure and attack surface.

### Container Security Best Practices
- Run **rootless containers** whenever possible
- Use **SELinux/AppArmor** profiles for containers
- Regular image scanning for vulnerabilities
- Don't run containers as root inside the container
- Use read-only filesystems where possible
- Limit container capabilities (drop all, add only needed)

## 5. Personal OPSEC Recommendations

### Digital Identity
1. **Use unique, strong passwords** for every service (password manager essential)
2. **Enable phishing-resistant MFA** (hardware keys like YubiKey, or TOTP — avoid SMS where possible)
3. **Use separate email addresses** for different risk levels (banking, social, shopping, throwaway)
4. **Freeze credit reports** if applicable in your jurisdiction

### Communication
1. **Use end-to-end encrypted messaging** (Signal, Matrix)
2. **Avoid sharing sensitive data** over unencrypted channels
3. **Be skeptical** of unsolicited contact — verify through independent channels

### Device Security
1. **Keep all devices updated** — auto-update where possible
2. **Use full-disk encryption** (LUKS on Linux, BitLocker on Windows, FileVault on macOS)
3. **Disable unused services/ports** on all devices
4. **Use a VPN** for untrusted networks (WireGuard self-hosted or Mullvad/ProtonVPN)

### Browsing Habits
1. **Use privacy-focused browser** (Firefox with uBlock Origin, or Brave)
2. **Block trackers and ads** at DNS level (Pi-hole/AdGuard)
3. **Use containerized browsing** for high-risk sites
4. **Clear cookies/cache** regularly or use temporary containers

### Backup Strategy (3-2-1 Rule)
- **3** copies of important data
- **2** different media types
- **1** offsite/cloud backup
- **Encrypt backups** before uploading to cloud
- **Test restores** regularly

### Social Engineering Defense
- **Verify independently** — if someone claims to be from your bank, call them back on a known number
- **Don't rush** — pressure tactics are a red flag
- **Be cautious with links** — hover to check URLs, use URL scanners
- **Young threat actors** (like Scattered Spider) excel at persuasive, native-language social engineering
